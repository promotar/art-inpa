# Setup and Deployment Guide

## Overview

This application is a Laravel project with Vite for asset bundling. It's designed to work in both development and production environments using Docker.

## Important: Vite Assets and the `manifest.json` File

### What is manifest.json?

The `manifest.json` file is generated by Vite during the asset build process. It contains a mapping of asset sources to their built/optimized versions.

### Why is it Important?

- **In Development**: Vite runs a dev server that handles assets dynamically
- **In Production**: You need a built `manifest.json` file for Laravel to find optimized assets
- **Problem**: The `/public/build` directory (including `manifest.json`) is in `.gitignore` because it's generated, not source code

## Setup Instructions

### For Local Development

1. Clone the repository
   ```bash
   git clone <repo-url> art-inpa
   cd art-inpa
   ```

2. Copy environment file
   ```bash
   cp .env.example .env
   ```

3. Start Docker containers
   ```bash
   docker compose up -d --build
   ```

4. The Vite development server will automatically start and serve assets dynamically

### For Production/Remote Servers

#### Option 1: Automatic Build (Recommended)

Simply start the containers. The app will automatically:
1. Install PHP dependencies (composer)
2. Check for `public/build/manifest.json`
3. If missing, install Node.js, npm dependencies, and build assets

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

#### Option 2: Manual Build Before Deployment

Build locally before pushing or deploying:

**On Linux/macOS:**
```bash
./build-assets.sh
# Then commit and push
git add public/build
git commit -m "Add built Vite assets"
git push
```

**On Windows:**
```powershell
.\build-assets.bat
# Then commit and push
git add public/build
git commit -m "Add built Vite assets"
git push
```

Or manually:
```bash
npm install
npm run build
```

#### Option 3: Build in Docker Container

```bash
# Start the container
docker compose -f docker-compose.prod.yml up -d --build

# Build assets manually if needed
docker compose exec app npm install
docker compose exec app npm run build
```

## Troubleshooting

### Error: "Vite manifest not found"

This happens when the `public/build/manifest.json` file doesn't exist.

**Solution:**
```bash
# Check if build directory exists
ls public/build/
ls public/build/manifest.json

# If missing, rebuild
docker compose exec app npm run build

# Or on host machine (requires Node.js):
npm install
npm run build
```

### Assets Don't Load or Styling is Missing

**Solution:**
1. Verify manifest.json exists: `public/build/manifest.json`
2. Check container logs: `docker compose logs app`
3. Manually rebuild: `npm run build` or `npm run dev` (for development)

### Docker Build Process Fails

Check the logs for where it failed:
```bash
docker compose logs app
```

Common issues:
- Insufficient disk space
- Insufficient memory (Node.js build can be memory-intensive)
- Network issues during npm install

### Vite Dev Server Issues (Local Development)

The Vite container should run automatically. Check:
```bash
docker compose ps
docker compose logs vite
```

If the container isn't running:
```bash
docker compose up -d vite
```

## Files and Directories

- `/resources/css/` - Source CSS files (Tailwind)
- `/resources/js/` - Source JavaScript files
- `/public/build/` - **Generated by npm run build** (don't commit this usually, but auto-builds when needed)
- `/public/hot` - Vite HMR marker file (dev only)
- `vite.config.js` - Vite configuration
- `package.json` - Node dependencies and build scripts

## Environment-Specific Behavior

### Development (APP_ENV=local)
- Vite dev server runs in a separate container
- Assets are served dynamically
- No manifest.json needed

### Production (APP_ENV=production)
- No Vite server running
- Uses pre-built assets from `public/build/`
- Requires `public/build/manifest.json` to exist
- Auto-builds on first startup if needed

## Git and the Build Directory

The `/public/build` directory is git-ignored because:
1. It's generated code, not source code
2. It contains environment-specific artifacts
3. Different build environments produce different output

The app automatically handles this by:
- Building assets on startup if manifest.json is missing
- Ensuring everything works without manual intervention

## Best Practices

1. **Local Development**: Use `docker compose up -d` and the Vite dev server will handle everything
2. **Before Deployment**: Test in production mode locally first
3. **After Pulling**: If you see "manifest not found" errors, the app will auto-fix on restart
4. **Cache Busting**: Vite handles this automatically; no action needed

## Quick Reference

| Task | Command |
|------|---------|
| Start development | `docker compose up -d` |
| Start production | `docker compose -f docker-compose.prod.yml up -d` |
| View logs | `docker compose logs -f app` |
| Rebuild assets manually | `npm run build` (host) or `docker compose exec app npm run build` |
| Watch assets (dev) | `npm run dev` (host) or automatic via `art-inpa-vite` container |
| Stop containers | `docker compose down` |

## Support

If you encounter issues:

1. Check logs: `docker compose logs app`
2. Verify manifest exists: `ls -la public/build/manifest.json`
3. Manually rebuild: `docker compose exec app npm run build`
4. Nuclear option: `docker compose down && docker compose up -d --build`
